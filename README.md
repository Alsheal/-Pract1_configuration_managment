# Эмулятор командной оболочки ОС

Учебный проект по разработке эмулятора командной оболочки UNIX-подобной операционной системы.

> **Текущий этап: Этап 2 — Конфигурация**

---

# Описание

Данный проект представляет собой графический эмулятор командной оболочки.

На первом этапе реализован минимальный интерактивный прототип, который позволяет пользователю вводить команды через графический интерфейс, разбирать их аргументы и получать результат выполнения.

На втором этапе функциональность расширена за счёт параметров запуска, загрузки стартового скрипта и диагностического вывода конфигурации.

Эмулятор имитирует работу UNIX-подобной командной строки. На текущем этапе команды `ls` и `cd` остаются заглушками и не выполняют реальные операции с файловой системой.

---

# Цели этапа 1

В рамках первого этапа необходимо было:

- создать приложение с графическим интерфейсом;
- реализовать интерактивный режим работы;
- формировать заголовок окна на основе данных операционной системы;
- реализовать парсер команд;
- обеспечить корректную обработку аргументов в кавычках;
- реализовать команды `ls` и `cd` в виде заглушек;
- реализовать команду `exit`;
- добавить обработку ошибок;
- продемонстрировать работу прототипа в интерактивном режиме.

## `main.py`

Основной файл приложения.

Отвечает за:

- создание графического окна;
- создание элементов GUI;
- получение имени пользователя;
- получение имени компьютера;
- обработку пользовательского ввода;
- отображение команд и результатов;
- получение параметров конфигурации;
- запуск стартового скрипта;
- вывод диагностической информации о запуске.

## `emulator.py`

Содержит основную логику обработки команд.

Отвечает за:

- получение строки команды;
- передачу команды парсеру;
- обработку ошибок разбора;
- передачу аргументов обработчику команд;
- возврат результата выполнения команды.

## `parser.py`

Содержит парсер команд.

Для корректной обработки кавычек используется стандартный модуль Python `shlex`.

Парсер преобразует введённую строку в список команды и её аргументов.

Например:

```text
cd "my folder"
```

Результат разбора:

```python
["cd", "my folder"]
```

## `commands.py`

Содержит реализацию поддерживаемых команд:

- `ls`;
- `cd`;
- `exit`.

На первом и втором этапах `ls` и `cd` являются заглушками. Команда `exit` завершает работу приложения.

## `config.py`

Содержит обработку параметров командной строки.

Отвечает за:

- определение параметров запуска;
- получение пути к каталогу-источнику виртуальной файловой системы;
- получение пути к стартовому скрипту;
- преобразование переданных путей в абсолютные;
- формирование конфигурации для приложения.

## `startup.py`

Отвечает за работу со стартовым скриптом.

Реализует:

- чтение команд из текстового файла;
- последовательную обработку команд;
- пропуск пустых строк и комментариев;
- отображение команд и результатов выполнения;
- прекращение выполнения скрипта при команде `exit`.

Ошибки отдельных команд отображаются в интерфейсе, но не должны останавливать выполнение последующих команд.

# Поддерживаемые команды

## `ls`

На первом и втором этапах команда `ls` реализована как заглушка.

При вводе команды выводятся её название и переданные аргументы.

### Без аргументов

```text
$ ls
Команда: ls
Аргументы: []
```

### С аргументом

```text
$ ls test
Команда: ls
Аргументы: ['test']
```

### С несколькими аргументами

```text
$ ls test folder
Команда: ls
Аргументы: ['test', 'folder']
```

На текущем этапе команда не выполняет реальный просмотр файловой системы. Работа с виртуальной файловой системой будет реализована на третьем этапе.

## `cd`

Команда `cd` также является заглушкой.

### Пример

```text
$ cd test
Команда: cd
Аргументы: ['test']
```

### Несколько аргументов

```text
$ cd test folder
Команда: cd
Аргументы: ['test', 'folder']
```

На первом и втором этапах команда не изменяет текущий каталог. Реальная работа с каталогами будет добавлена при реализации VFS.

## `exit`

Команда `exit` завершает работу приложения.

### Пример

```text
$ exit
```

После выполнения команды графическое окно эмулятора закрывается.

# Обработка аргументов в кавычках

Для разбора команд используется стандартный модуль Python `shlex`.

Парсер поддерживает аргументы, заключённые в кавычки.

Например, команда:

```text
cd "my folder"
```

разбирается как:

```text
Команда: cd
Аргументы: ['my folder']
```

Таким образом, `my folder` воспринимается как один аргумент, несмотря на наличие пробела.

### Пример с несколькими аргументами

Ввод:

```text
ls "hello world" test
```

Результат:

```text
Команда: ls
Аргументы: ['hello world', 'test']
```

# Обработка ошибок

Эмулятор обрабатывает неизвестные команды и ошибки синтаксического разбора.

## Неизвестная команда

Например:

```text
$ hello
Ошибка: неизвестная команда 'hello'
```

Неизвестная команда не приводит к завершению приложения — пользователь может продолжить работу.

## Ошибка парсинга

При вводе незакрытой кавычки:

```text
$ cd "test
```

будет выведено сообщение об ошибке разбора команды.

После обработки ошибки эмулятор продолжает работать.

## Параметры запуска

Для настройки приложения используются параметры командной строки.

| Параметр | Назначение | Значение по умолчанию |
|---|---|---|
| `--vfs` | Путь к каталогу-источнику виртуальной файловой системы | `vfs` |
| `--script` | Путь к стартовому скрипту | Не задан |

Параметр `--vfs` позволяет передать путь к каталогу, который будет использоваться при реализации виртуальной файловой системы на третьем этапе.

Параметр `--script` указывает файл с командами, которые необходимо выполнить при запуске приложения.

На втором этапе путь к VFS сохраняется в конфигурации. Полноценная работа с содержимым виртуальной файловой системы пока не реализована.

## Запуск с параметрами

Запуск без дополнительных параметров:

```bash
python main.py
```

Запуск с указанием VFS и стартового скрипта:

```bash
python main.py --vfs "vfs" --script "scripts/startup.txt"
```

В Windows можно использовать:

```powershell
py main.py --vfs "vfs" --script "scripts\startup.txt"
```

При запуске с параметрами программа получает указанные пути и использует их при настройке эмулятора.

## Диагностический вывод

При запуске приложения в терминал выводится информация о параметрах запуска.

Пример:

```text
=== Параметры запуска эмулятора ===
VFS path: /path/to/project/vfs
Startup script: /path/to/project/scripts/startup.txt
Python executable: /path/to/python
Working directory: /path/to/project
Username: student
Hostname: computer
===================================
```

Фактические значения зависят от операционной системы, имени пользователя, расположения проекта и переданных параметров.

Диагностический вывод позволяет проверить, какие параметры получила программа и какие пути использует при запуске.

## Стартовый скрипт

Стартовый скрипт — текстовый файл, содержащий команды эмулятора, записанные по одной на строку.

Пример содержимого `scripts/startup.txt`:

```text
# Проверка команд этапа 1
ls
ls "папка с пробелами"
cd documents
cd "папка с пробелами"
unknown_command
ls -l
```

Пустые строки и строки, начинающиеся с `#`, пропускаются.

При запуске с параметром `--script` приложение:

1. Открывает указанный файл.
2. Читает команды последовательно.
3. Передаёт каждую команду обработчику эмулятора.
4. Отображает команду и результат выполнения в GUI.
5. Продолжает выполнение после ошибки отдельной команды.
6. Прекращает выполнение скрипта, если встречается команда `exit`.

Если файл стартового скрипта не найден или не может быть прочитан, приложение выводит сообщение об ошибке.

## Скрипты запуска операционной системы

Для упрощения запуска подготовлены отдельные скрипты.

### Windows — `scripts/run_windows.bat`

Скрипт запускает эмулятор из корневого каталога проекта с параметрами `--vfs` и `--script`.

Запуск из CMD:

```cmd
scripts\run_windows.bat
```

### Linux/macOS — `scripts/run_unix.sh`

Скрипт запускает приложение с помощью `python3`.

Перед первым запуском при необходимости нужно предоставить права на исполнение:

```bash
chmod +x scripts/run_unix.sh
```

Запуск:

```bash
./scripts/run_unix.sh
```

Оба скрипта передают приложению путь к VFS и путь к стартовому сценарию.
